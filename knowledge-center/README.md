# Nezam636 Knowledge Center

نسخه پایه و مستقل بانک دانش هوشمند دفتر ۶۳۶ خفر. این پوشه مستقل از صفحه اصلی اتوماسیون است و فایل‌های ریشه پروژه را تغییر نمی‌دهد.

## قابلیت‌های فعال در این نسخه
- رابط فارسی راست‌چین و واکنش‌گرا، بدون کتابخانه و CDN خارجی
- ذخیره محلی اسناد در IndexedDB و قابل استفاده بدون اینترنت
- نگهداری فایل اصلی به‌صورت Blob
- استخراج متن ساده از TXT، MD، CSV، JSON، XML، HTML و RTF
- ثبت عنوان، دسته‌بندی، مرجع، شماره/تاریخ، وضعیت اعتبار و یادداشت اجرایی
- پیشنهاد اولیه دسته‌بندی بر اساس کلیدواژه (صرفاً پیشنهاد، نه تشخیص قطعی)
- جست‌وجو در اطلاعات و متن ثبت‌شده، مشاهده جزئیات، دریافت فایل و حذف
- پشتیبان‌گیری و بازیابی اطلاعات همراه با فایل‌های اصلی

## محدودیت‌های شفاف
PDF، تصویر اسکن‌شده، DOC قدیمی، DOCX، XLSX و PPTX در این نسخه به‌عنوان فایل اصلی نگهداری می‌شوند اما هنوز متن آن‌ها به‌صورت خودکار استخراج نمی‌شود. OCR، استخراج کامل Office/PDF، اتصال واقعی Drive، تحلیل هوش مصنوعی و افزونه Chrome بله در ماژول‌های بعدی ساخته و جداگانه آزمون خواهند شد. رابط کاربری هیچ‌یک از این قابلیت‌های هنوز پیاده‌نشده را فعال نمایش نمی‌دهد.

## معماری هدف
1. مخزن محلی IndexedDB برای فایل، متن، فراداده، قطعات متن و وضعیت بازبینی.
2. مخزن ابری Google Drive در مسیر Nezam636_Automation_Archive/Knowledge_Base/ با نگهداری نسخه اصلی و تاریخچه تغییرات.
3. همگام‌سازی با شناسه پایدار، کنترل checksum، صف ارسال، retry/backoff و مدیریت تعارض.
4. استخراج PDF و Office، OCR فارسی، نرمال‌سازی متن و ثبت شماره صفحه/بخش منبع.
5. مدل دانش حقوقی شامل سند، ماده، بند، تبصره، تکلیف، شرط، مدرک، مرجع، مهلت، گام اجرایی، اصلاحیه و نسخ.
6. جست‌وجوی ترکیبی کلیدواژه و معنایی و پاسخ مستند با عنوان سند، شماره ماده و صفحه.
7. بازبینی انسانی؛ خروجی هوش مصنوعی پیش‌نویس است و تا تأیید کارشناس، قانون معتبر تلقی نمی‌شود.
8. افزونه Chrome بله برای استخراج دستی/کاربرمحور محتوای قابل مشاهده در گروه‌های مجاز؛ بدون دور زدن کنترل دسترسی یا جمع‌آوری داده خصوصی اعضا.

## قرارداد موردنیاز برای اتصال Drive
سمت Apps Script باید عملیات فهرست اسناد دانش، بارگذاری اصل سند، بارگذاری متن استخراج‌شده، دریافت سند، ثبت tombstone برای حذف، همگام‌سازی شاخص و دریافت تغییرات را پیاده‌سازی کند. قبل از نوشتن آداپتور، باید کد واقعی Apps Script فعلی و نام عملیات‌های پشتیبانی‌شده بررسی شود. کلید دسترسی و کلید Gemini نباید داخل فایل‌های استاتیک GitHub Pages قرار گیرند.

Apps Script محدودیت زمان هر اجرا و سهمیه روزانه دارد؛ بنابراین OCR و پردازش حجیم باید قطعه‌بندی و صف‌بندی شوند، نه در یک درخواست طولانی.

## اجرا
برای توسعه، پوشه knowledge-center را با VS Code Live Server یا یک وب‌سرور محلی اجرا کن. داده IndexedDB به مبدأ و پروفایل مرورگر وابسته است؛ برای دسترسی به همان بانک محلی، از همان مرورگر و همان نشانی استفاده کن. فایل JSON پشتیبان را در محل امن دیگری نیز نگهداری کن.

پس از ادغام و انتشار فایل‌های این شاخه، مسیر زیر در صورتی در دسترس است که GitHub Pages کل محتوای مخزن را منتشر کند:
